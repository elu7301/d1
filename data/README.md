# Реальные данные M5

Файл `m5_sales.csv` — подмножество реальных продаж Walmart из M5 Forecasting — Accuracy.
Данные добавлены в проект 15.10.2026; генерации искусственных наблюдений нет.

## Источники

- [Описание данных на Kaggle](https://www.kaggle.com/competitions/m5-forecasting-accuracy/data).
- [Руководство организаторов M5](https://storage.googleapis.com/kaggle-forum-message-attachments/772349/15032/M5-Competitors-Guide-Final-10-March-2020.pdf).
- [Архив файлов на Zenodo, DOI 10.5281/zenodo.10203108](https://zenodo.org/records/10203108).

Из архива использованы строки `sales_train_evaluation.csv`, `sell_prices.csv`
и календарь `calendar.csv`. Условия использования указаны в правилах
исходного соревнования Kaggle; отдельная свободная лицензия архивом не заявлена.

## Состав и преобразования

Взяты магазин `CA_1` и три заранее фиксированных кода продовольственных товаров:
`FOODS_3_090`, `FOODS_3_252`, `FOODS_3_586`. Товары не отбирались по точности моделей.
Это небольшой пример для изучения, он не представляет весь ассортимент сети.

Исходные продажи `d_1`–`d_1941` развёрнуты в строки «товар — день».
Дата определена по `calendar.csv`, цена присоединена по `store_id`, `item_id`
и `wm_yr_wk`. Для каждого товара сохранены все 1941 исходных значения продаж.
Период — 29.01.2011–22.05.2016, всего 5823 строки.
Продажи не сглажены и не изменены; нули присутствуют в источнике.
Пропущенные дни и цены не заполнялись. У выбранных товаров цена известна
для каждой недели периода.

| Столбец | Значение |
| --- | --- |
| `date` | Дата из календаря M5, `ГГГГ-ММ-ДД` |
| `sku` | Исходный обезличенный код `item_id` |
| `store_id` | Исходный код магазина, в этом файле всегда `CA_1` |
| `sales` | Исходное целое неотрицательное количество проданных единиц за день |
| `price` | `sell_price`, средняя цена за неделю в долларах США; повторена для дней недели |
| `snap` | `snap_CA`, календарный признак SNAP для Калифорнии, 0 или 1 |
| `event` | 1, если заполнено `event_name_1` или `event_name_2`, иначе 0 |

SNAP не является признаком скидки или промоакции конкретного товара.
Отдельный `promo` не создавался. Нулевые продажи не доказывают отсутствие спроса:
в наборе нет дневных запасов и сведений о наличии на полке.
Недельная средняя цена не равна журналу фактических цен каждой покупки,
поэтому точную дневную выручку по этим полям восстановить нельзя.

При проверке прогноза используются последние 28 дней: 25.04.2016–22.05.2016.
Фактические цены этих дней в модель не передаются: сохраняется последняя
цена обучающего периода. Календарь событий и SNAP предполагается известным заранее.

Контрольная сумма SHA-256 подготовленного CSV:

```text

```

Для своего CSV обязательны `date`, `sku`, `sales`, `price`, `snap`, `event`.
`store_id` необязателен; если он есть, в файле должен быть ровно один магазин.
Нужна одна строка на товар и дату, одинаковый полный дневной календарь товаров.
Программа отклоняет пропуски вместо автоматического заполнения нулями.
