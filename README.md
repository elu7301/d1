# Сценарное планирование в розничной торговле

Проект ВКР Королева Дмитрия Геннадиевича по подписанному плану-заданию.
Сейчас готовы текст первой главы и анализ реальных продаж из набора M5.

## Структура

```text
Diplom/
  main.py           единый запуск
  requirements.txt  библиотеки
  chapter1/         анализ, прогнозы, проверки и готовый Word
  chapter2/         место для проектирования системы
  chapter3/         место для итоговой системы и интерфейса
  common/           общие функции и соединение глав
  data/             реальные продажи и описание источника
```

Все папки находятся на одном уровне. Общие функции подключаются импортами,
без копирования файлов между главами.

Для GitHub пока включены только `chapter1`, `common`, используемые файлы `data`
и корневые файлы запуска и инструкции. Папки `chapter2` и `chapter3` остаются
локальными до следующего этапа. План-задание никогда не публикуется:
он исключён через `.gitignore`, как и остальные PDF, окружение и настройки IDE.

## Запуск

Нужен Python 3.12 или новее. В PyCharm выберите `.venv/bin/python`
и запустите корневой `main.py`. Библиотеки в текущем окружении установлены.

```bash
source .venv/bin/activate
python main.py
```

После клонирования репозитория создайте окружение и установите зависимости
(команда `python3` должна запускать Python 3.12 или новее):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

По умолчанию программа читает `data/m5_sales.csv`, проверяет данные и выводит
показатели и ошибки моделей в консоль. Входной CSV не изменяется.
Для просмотра графиков на экране:

```bash
python main.py --plots
```

Генератора данных, создания Word и автоматического сохранения CSV, JSON
или изображений в проекте больше нет. При расчёте новые файлы результатов
не создаются. При ручном сохранении графика через окно Matplotlib файл выбирает
сам пользователь.

## Данные и расчёт

Использовано подмножество реальных данных Walmart M5: магазин `CA_1`, товары
`FOODS_3_090`, `FOODS_3_252`, `FOODS_3_586`. Период — 29.01.2011–22.05.2016,
1941 день на товар, всего 5823 строки. Названия товаров в наборе обезличены.
Источник, преобразования и контрольная сумма приведены в [data/README.md](data/README.md).

Программа сравнивает среднее последних 7 дней, повторение последней недели
и линейную Ridge-регрессию. Последние 28 дней отложены для проверки;
прогноз строится сразу на весь период. Для изменения горизонта:

```bash
python main.py --horizon 14
```

Линейная модель использует прошлые продажи, тренд, день недели, годовой цикл,
цену и календарные признаки `snap` и `event`. SNAP — календарный признак
программы продовольственной помощи США; он не обозначает скидку магазина.
Календарь считается известным заранее. Будущая цена сохраняется на последнем
значении обучения: фактические цены проверочного периода модель не получает.
Пропущенные будущие лаги заполняются собственными прогнозами модели.

MAE и RMSE измеряются в единицах товара, WAPE — в процентах.
Положительное `bias_units` означает завышение прогноза.
`ALL` объединяет ошибки всех товаров: WAPE считается по суммам ошибок и продаж.
При нулевой сумме продаж WAPE выводится как `NaN`.

На периоде 25.04.2016–22.05.2016 общая WAPE: линейная модель — 18,90%,
сезонный наивный прогноз — 25,06%, среднее за 7 дней — 26,53%.
Это локальный результат по трём товарам и одной точке начала прогноза,
а не результат соревнования M5 и не оценка всех магазинов Walmart.

В наборе нет остатков, закупочной себестоимости и реальных сроков поставки.
Код прогнозирует наблюдаемые продажи; потерянный спрос и прибыль не вычисляет.
Для следующих глав эти параметры понадобятся отдельно, с указанием допущений.

## Порядок изучения кода

1. `main.py` и `common/main.py` — общий запуск и подключение глав.
2. `chapter1/main.py` — последовательность работы.
3. `common/data.py` — загрузка CSV и проверка таблицы.
4. `chapter1/analysis.py` — показатели и рисунки в памяти.
5. `chapter1/forecast.py` — признаки, обучение, прогноз и сравнение.
6. `common/metrics.py` — формулы ошибок.
7. `chapter1/test_project.py` — проверки на реальных данных, без создания файлов.

```bash
python -m unittest discover -s chapter1 -v
```

Проверяются независимость прогноза от будущих фактов и цен, базовый прогноз,
неполный календарь, дубликаты, неверные значения, WAPE при нулевом знаменателе
и другой горизонт. Проверки читают тот же файл M5.

Собственный файл можно передать так: `python main.py --data data/my_sales.csv`.
Формат столбцов описан в `data/README.md`. Нужны один магазин, одинаковый полный
дневной календарь всех товаров и как минимум 56 обучающих дней плюс горизонт.
